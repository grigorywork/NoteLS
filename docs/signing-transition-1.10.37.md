## Переустановка без потери данных

Перед удалением старого NoteLS экспортировать зашифрованную копию в «Загрузки» или другую папку вне данных приложения и сохранить переносимый пароль копии. Внутренние автоматические копии удаляются вместе с приложением. Старой биометрии после переустановки недостаточно: локальный Android Keystore и его привязка могут исчезнуть. Пароль в чат не передавать.

Первый APK с новым сертификатом не устанавливается поверх прежнего APK с другим сертификатом. После первой установки все будущие устанавливаемые APK должны иметь один и тот же новый сертификат; package/applicationId остаётся `com.notessync.app`. Из старого APK извлечь приватный ключ подписи нельзя.

## Хранение ключа

`scripts/bootstrap_signing.py --initialize-new-key --private-dir <отдельная-приватная-папка-вне-репозитория>` запускается владельцем один раз после входа GitHub CLI с правом записи repository Actions Secrets. JDK17/keytool должны быть доступны. Команда проверяет доступ до создания ключа; создание в GitHub Actions запрещено.

Новая identity: RSA3072/SHA256withRSA/PKCS12, alias `notels-2026`, срок10000 дней. Случайный пароль генерируется без ввода/вывода в чат. В GitHub сохраняются `NOTELS_KEYSTORE_BASE64` и `NOTELS_SIGNING_PASSWORD`; в Git отслеживается только публичный SHA256 сертификата. Приватные файлы не входят в исходники, отчёты, APK-артефакт или выпуски. При частичном отказе сохранения сохранять приватный каталог и продолжать с тем же ключом; новый ключ вместо него не генерировать. Уже закреплённую identity bootstrap не заменяет.

После настройки проверить фактическую подпись APK из CI. Не удалять/не перезаписывать Secrets: это постоянная identity будущих обновлений. Смена облачной рабочей среды не должна менять ключ. Наличие Secrets проверяется по именам, их значения GitHub обратно не выдаёт.

## Сборка и ограничения

Обычный `Android checks` по-прежнему проверяет debug/JUnit/lint; его Android Debug/NOT-UPDATE артефакт не является устанавливаемым постоянным выпуском.

`Signed NoteLS APK` запускается после успешного push-прогона `Android checks` на main; pull requests/forks не получают Secrets. Без публичного сертификата выпуск явно пропускается. С закреплённой identity отсутствие/ошибка Secrets останавливают выпуск. Локально без keystore.properties `assembleRelease` создаёт unsigned APK, без временного fallback-ключа; прежняя локальная настройка подписи через keystore.properties сохранена.

`scripts/sign_apk.py` принимает готовый недебажный release APK, проверяет package/version, подписывает существующим ключом и проверяет настоящий сертификат Android apksigner до записи в upload directory. Если ключ другой, пароль неверен, Secrets отсутствуют или сертификат не совпадает, APK не публикуется. Выход содержит только APK, SHA256SUMS, README с sourceSHA/публичным отпечатком и инструкцией первой установки. Логи не должны содержать private key, пароль или содержимое Secrets.

Проверки подписи выполняются `scripts/test_sign_apk.py` на настоящем unsigned release APK и двух одноразовых тестовых ключах. Эти временные ключи не становятся identity NoteLS и не используются в выдаваемом APK. Их число проверок указывается отдельно от661 обычного набора предыдущей1.10.36; прошлый результат не выдаётся за новый прогон.

Устанавливаемый APK с новой постоянной подписью будет готов только после подтверждённого сохранения Secrets и сверки фактического сертификата/версии/source/hash. Облачные проверки не являются замерами телефона.
