# Этап 41 — фоновая активность и ресурсы

Дата: 2026-11-11. Исходная точка: `main`, `1528cec421dad875e4e7e0a0aee52646300b2140`.
Версия исходников после исправлений: **1.10.2 / versionCode 25**.

## Подтверждённые дефекты и исправления

1. `TaskTimerIndicator` и `CountdownIndicator` обновляли состояние каждую секунду в `LaunchedEffect`, пока экран оставался в композиции, включая остановленную Activity. Обновления теперь ограничены `Lifecycle.State.STARTED`; при возвращении время пересчитывается по абсолютной отметке. Завершившийся отсчёт прекращает секундные обновления. Анимация песочных часов также исключается из композиции при остановке UI.
2. `SyncViewModel.cancel()` закрывал только слушающий сервер; подключающийся или уже подключённый сокет оставался в блокирующем connect/read (до 10/120 секунд). Отдельный владелец ресурсов каждой сессии теперь закрывает все сокеты при отмене, включая ресурс, полученный одновременно с отменой. При выходе назад, переходе к сканеру и остановке Activity активная сессия отменяется. Отменённая корутина не сообщает об обычной ошибке соединения. ViewModel по-прежнему создаётся только при открытии синхронизации/сканера.
3. Голосовой ввод освобождался только через `onDispose`. Теперь `ON_STOP` редактора останавливает распознаватель и сбрасывает индикатор записи, даже если экран остаётся в композиции.
4. Аудит выявил незакрытые executor и ML Kit scanner в QR-сканере. После выхода снимается анализатор, отвязываются его CameraX use cases, закрывается scanner и останавливается executor. Поздний ответ provider не привязывает камеру после выхода; поздний результат распознавания не запускает синхронизацию при скрытом экране.

## Проверенные пути активности

| Узел | Поведение и границы |
|---|---|
| Activity и Flow | UI использует `collectAsStateWithLifecycle`; списки Room разделяются через `WhileSubscribed(5000)`. После остановки подписчиков нет постоянного опроса БД. Ожидание события в autosave не является циклом опроса. |
| Таймеры | Секундные обновления нужны видимому UI; в фоне не выполняются. Пользовательские напоминания и окончание отсчёта используют одноразовые AlarmManager, а не секундную службу. |
| Виджет | В обеих версиях XML `updatePeriodMillis=0`. Обновление по событиям, запрос диапазона 42 дней конечный. RemoteViewsService обслуживает запросы лаунчера, не является started/foreground service. |
| Бэкап | Запрос по входу/выходу Activity и изменению записи; `BackupPolicy` проверяет срок. IO-корутина конечная, операции ограничены mutex. После ухода UI уже начатая копия может закончить запись, чтобы сохранить целый архив. Нет таймера, WorkManager, службы или wake lock. |
| Цитаты и шрифты | Цитата дня обновляется на `ON_RESUME`, фильтр сохранён. Шрифты и лицензии локальные; в настройках один выбранный предпросмотр. Фоновых сетевых загрузок шрифтов нет. |
| Сеть и микрофон | TCP запускается явно для синхронизации и закрывается при уходе. Системное распознавание речи запускается пользователем; онлайн-режим может обращаться к сети, до `ON_STOP`. Автоматического повторного подключения и сетевого опроса не найдено. |
| BootReceiver | Однократное восстановление будущих напоминаний после загрузки ОС; постоянной службы нет. |

Это выводы по исходникам и регрессионным тестам, а не доказательство нулевого энергопотребления. Android и лаунчер могут держать процесс и RemoteViews в кэше; наличие процесса само по себе не означает активную работу.
