## Файловый обмен

Протокол/шифрование/лимиты64 и доверие65 не меняются. Реальный Room source поддерживает отдельную optional StreamingSyncDataSource capability: отправитель держит открытый descriptor и читает до256KiB, приёмник пишет во временный файл через64KiB buffer, одновременно считает SHA-256/число байтов. Нет целого вложения в ByteArrayOutputStream/toByteArray у настоящего обмена Room. Старый byte-array контракт остаётся совместимым адаптером для старых/test источников, включая Kotlin delegation: их переопределения read/write продолжают вызываться.

Общий VerifiedAttachmentSink проверяет предел при каждом write и точный размер/хеш перед публикацией. Усечение, рост источника, неожиданный chunkID, лишние/неполные байты, неверный хеш и отмена завершают сеанс без ACK/публикации неполного файла. use/close закрывают descriptor и удаляют staging при любом выходе. Успешный поток flush/fsync до короткой Room-транзакции, внутри повторная проверка существования/purge/владельца и atomic rename+обновление previewRevision/size. Родитель, удалённый во время передачи, не возрождается. Legacy write сохраняет ранний purge no-op.

Staging в private attachments/.sync-incoming на том же томе, не среди записей вложений/ручного бэкапа. Исключён из legacy/cloud/device-transfer OS backups; при первом приёме в сеансе удаляются только собственные receive-*.tmp старше30 минут, свежие не трогаются. Нет нового фонового уборщика/службы/периодического опроса.

## SQL и отмена

Согласованный снимок метаданных теперь содержит SQL/проекции: LEFT JOIN глобального syncId блокнота, вложения и теги пачками по200 noteIDs вместо запросов на каждую заметку. Файловые open/hash выполняются после выхода из snapshot transaction. Это сохраняет notebook/tag/file соответствия, в том числе неизменённого блокнота, и допускает конкурирующую транзакцию во время хеширования. Обычное snapshot-хеширование читает по32KiB и проверяет отмену между чтениями. Подтверждения версий сгруппированы по128 коротких транзакций, conditional dirty/version guard и ACK только после mutual DONE сохраняются. Убраны временные flatMap/map списки при регистрации объявленных файлов.

Редкая атомарная транзакция конфликтной копии по-прежнему включает независимое копирование/проверку её файлов; её целостность не ослаблялась. Метаданные протокола пока wholebatch в памяти с прежним лимитом кадра32MiB: полная память синхронизации не объявляется ограниченной размером одного куска. Общий wall-clock cursor не возвращался, full snapshot предотвращает потерю данных нескольких peers.
