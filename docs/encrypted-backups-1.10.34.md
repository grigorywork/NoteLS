# Этап67а: зашифрованные резервные копии

Версия1.10.34/code57, Room17, JSONdata2/security3. Локально560 тестов/129 наборов,0 failures/errors/skipped; lint0 ошибок/15 предупреждений/2 информации, assembleDebug успешно за12m 20s. CI/APK ожидаются; до сверки этап не закрыт.

В настройках резервных копий пользователь задаёт отдельный пароль минимум8 символов с подтверждением. До настройки ручной экспорт завершается ошибкой, автоматический не создаёт файлов. Все новые ручные/автоматические копии имеют формат `.nlsbackup`, без переключателя на открытый ZIP. Пароль не запрашивается в чате и не записывается в настройки. Частота автоматических копий остаётся событийной, без фонового таймера/службы.

Пароль переносим: заголовок файла содержит публичный ключ и зашифрованную паролем приватную часть, поэтому восстановление на другом телефоне не требует прежних настроек приложения. При смене пароля меняется оболочка того же ключа. Ранее выгруженные файлы сохраняют прежний пароль; новый пароль открывает новые копии. Импорт не подменяет получателя будущих автоматических копий.

Биометрия включается после подтверждения пароля копий. Отдельный ключ AndroidKeyStore AES256-GCM требует сильной биометрии для каждого использования, инвалидируется при изменении зарегистрированных отпечатков и оборачивает настоящую приватную часть ключа копий. Подтверждение через CryptoObject проверяется по идентичности Cipher и используется однократно. Обычный системный PIN/маркер успешного UI не заменяет расшифрование. Биометрическая оболочка работает только на исходном устройстве; шаблон отпечатка не хранится в приложении и не входит в копию. Пароль остаётся резервным способом при отсутствии/потере ключа/недоступности сенсора.

При уходе приложения с экрана/закрытии диалога ожидающие разблокировки отзываются, приватные leases закрываются; поздний callback не открывает другую копию. Подтверждённое восстановление владеет своим lease до `finally`. Пароли/lease не входят в SavedState, Room, синхронизацию или архив. Шифрованная настройка и локальная биометрическая оболочка лежат в отдельных private preferences. Доступ к уже работающему/скомпрометированному устройству и открытая база приложения на нём не входят в защиту экспортируемого файла.

## Формат1

- Magic8 байт `NoteLSB1`, big-endian длина заголовка Int32, строгий UTF-8 JSON не более16КиБ: identity(publicKey,salt,rounds,privateIv,privateData), createdAt, wrappedKey, nonce. Неизвестные поля/недопустимые размеры отклоняются. Алгоритмы фиксированы версией, без понижения до открытого формата.
- RSA2048 с exponent65537. Приватный PKCS8 зашифрован AES256-GCM, случайные salt16/IV12, PBKDF2-HMAC-SHA256600000 итераций. При чтении ограничены итерации100000–1000000; AAD оболочки привязывает publicKey/salt/rounds. Приватная и публичная части проверяются как пара, без зависимости от CRT-интерфейса Android-провайдера.
- На файл новый случайный ключ32 байта, RSA-OAEP SHA256 с MGF1-SHA256. Автокопированию достаточно публичного ключа: открытая приватная часть/пароль для записи не нужны.
- Поток AES256-GCM: записи до64КиБ plaintext. Каждая запись: kind1байт, sequenceInt32, ciphertextLengthInt32, ciphertext+tag16. IV = случайный prefix8 + sequenceInt32. AAD = SHA256(magic+точные байты JSON) + kind/sequence/ciphertextLength. Индекс начинается с0; перестановка/повтор/подмена/изменение заголовка не проходят проверку. Обязательна отдельная аутентифицированная пустая конечная запись kind1 и затем EOF, без хвоста. Это шифрование для публичного получателя, а не подпись автора файла.
- Верхние пределы: ZIP-поток2ГиБ+64МиБ, распаковка2ГиБ/100000 записей, bounded заголовок/запись до выделения памяти. Контейнер не собирается целиком в ByteArray и не сохраняется временным открытым ZIP. Частные snapshot DB и извлечённые файлы остаются необходимыми временными файлами восстановления; это не шифрование всей рабочей базы на диске.

## Совместимость и аудит

Старый открытый ZIP восстанавливается после явного предупреждения и подтверждения полной замены данных. Экспорт старой локальной копии всегда оборачивает ZIP в новый шифрованный поток. После настройки пароля старые локальные автоматические копии переписываются через соседний шифрованный `.protecting`, fsync и атомарный rename; ошибка сохраняет оригинал и предлагает повторить. Уже отправленные наружу открытые ZIP нельзя защитить задним числом — их нужно заменить вручную. Политика последних5 копий очищает старые только после успешной новой записи.

Android `allowBackup=false`; legacy OS backup и обе ветви cloud/device-transfer исключают все области данных, включая device-protected storage. Это закрывает обход через системную копию открытой базы. Явные исключения секретов ИИ/синхронизации/бэкапа сохранены.

До живой транзакции проверяются все AEAD-записи и конечная запись, в том числе когда ZipInputStream уже завершил чтение/закрыл свой вход. Неверный пароль, подмена, обрыв и отмена не должны менять текущие заметки/вложения. Временные файлы чистятся в `finally`; прежний путь Room migration/schema/foreign keys/count/atomic transaction и остановка автообмена сохранены.

Границы доказательств: JCA/JVM, Native SQLite/Room и Native Compose в облаке. Реальный отпечаток, аппаратный Keystore телефона, OEM-перенос, скорость на A01, CPU/PSS/батарея не проверялись. Шифрование не запрещает скачивание уже доступного файла; оно защищает содержимое без секрета, устойчивость пароля важна. Постоянная подпись APK не менялась; облачный Android Debug APK — NOT-UPDATE.
