# Этап55б — биометрия защищённых блокнотов

1.10.20/code43, Room15, протокол2. Следующий этап56 — русский/английский интерфейс без перевода пользовательских данных.

## Использование

У защищённого открытого блокнота в меню есть «Включить биометрию». Требуются пароль этого блокнота и подтверждение в системном окне. После блокировки диалог входа предлагает «Открыть по биометрии»; обычный пароль остаётся доступен. Меню позволяет выключить биометрию. Отпечаток или другая сильная биометрия телефона; слабая распознаваемость лица и системный PIN не заменяют пароль блокнота. Нет доступного датчика/зарегистрированной биометрии — пароль, с пояснением в интерфейсе.

## Проверка доступа

AndroidNotebookBiometricVault изолирован за интерфейсом. На устройстве создаётся отдельный AES256/GCM-ключ Android Keystore с аутентификацией на каждое использование, BIOMETRIC_STRONG и invalidation при смене набора биометрии. Android26–29 используют per-use fingerprint API, Android30+ — явный AUTH_BIOMETRIC_STRONG. MainActivity наследует FragmentActivity для AndroidX BiometricPrompt; добавлены обычные разрешения USE_BIOMETRIC/USE_FINGERPRINT без обязательного hardware feature.

Успешный callback сам по себе доступа не даёт: нужен тот же Cipher, успешный doFinal и проверенный зашифрованный маркер. AAD связан с syncId блокнота и SHA256 текущего verifier/соли пароля. Пароль в открытом виде не сохраняется. Проверяются свежая строка БД, отсутствие удаления, актуальная привязка и одноразовый номер операции. Финальное разрешение выполняется на Main внутри транзакции проверки; повторные/устаревшие ответы отклоняются. ON_STOP и удаление экрана отменяют системный prompt и текущую операцию, включая ожидающий результат проверки. Смена пароля/блокнота, отсутствующий/инвалидированный ключ и повреждённые данные возвращают к паролю. Включение на другом телефоне выполняется отдельно.

Записи биометрии/ключи локальны и не передаются DTO/ручным бэкапом. После Android Auto Backup без соответствующего Keystore-ключа запись не даёт доступ. Удаление защиты/блокнота отзывает локальное разрешение. Осиротевшие ключи удаляются только в собственном пространстве имён при загрузке существующих записей или первом обращении к биометрии; ключи приложения для подписи APK не затрагиваются. Это проверка доступа к интерфейсу блокнота, не новое шифрование содержимого всей БД.

## Аудит и слабые устройства

Keystore, SharedPreferences и криптографические операции выполняются на IO; пароль проверяется на Default. При отсутствии сохранённых разрешений старт главной не обращается к Keystore. Нет нового фонового сервиса/опроса; одна текущая операция, короткие неизменяемые записи состояния. Общие сессии доступа обновляются атомарно. Изменения блокнотов читают свежие строки, не возвращают устаревший пароль при переименовании. Вход паролем также перепроверяет актуальные данные и отменяется при уходе с экрана.

Исправлен перенос сессий доступа при восстановлении: локальные ID могут быть повторно использованы другими защищёнными блокнотами, поэтому все разрешения сбрасываются внутри транзакции до публикации восстановленных данных. При получении изменений блокнота через обмен сессия закрывается до записи и публикации новых данных.

Подключены AndroidX Biometric1.1.0 и базовый Fragment1.8.5 без неиспользуемого KTX. Дополнительное GradleDependency-предупреждение сообщает о более новой версии Fragment; KtxExtensionAvailable — о необязательных расширениях. Обновление всего AndroidX-стека остаётся частью общей регрессии67; текущие версии проверены со SDK35/Activity1.9.3.
