# Невыполненные задачи и отдельный срок — этап62,1.10.27/code50, Room17

В боковом меню добавлены «Невыполненные» и «Просроченные». Сочетаются поиск, срок (любой/просроченные/сегодня/предстоящие/без срока), приоритет, блокнот/без блокнота и тег. Пункт «Задачи» сохраняет прежний показ всех задач. Новый порядок «По сроку»: закреплённые первыми, затем срок/приоритет/устойчивые даты/ID, записи без срока в конце своей группы. Большие списки блокнотов/тегов в новых фильтрах ленивые, пользовательские имена не переводятся.

В редакторе задачи отдельный выбор даты и времени срока с удалением; новое время по умолчанию23:59. Прошедший срок разрешён. Срок не включает напоминание/обратный отсчёт и не выводится из них. На карточках списка/сетки показан срок и отметка просроченности; выполненная задача не помечается просроченной. Завершение/корзина/восстановление сохраняют срок, окончательное удаление очищает его вместе с другими данными. Явное преобразование задачи в обычную заметку сбрасывает срок вместе с прочими настройками задачи. Задача только с датой не удаляется как пустой черновик.

## Хранение и обмен

Миграция16→17 добавляет nullable taskDueAt с DEFAULT NULL и индекс для активных сроков. Прежние reminderAt/dayKey/таймеры не изменяются и не становятся сроками. Основная/восстанавливаемая БД используют одну цепочку миграций. Бэкап сохраняет новое поле. Протокол2 сохраняется: optional TaskDeadlineDto отделяет отсутствие поля у старого клиента (сохранить текущий срок) от присутствующего объекта с at=null (явно убрать). Новые отправители посылают объект даже при пустом сроке. Проверены перенос/снятие/старый payload без поля/конфликтная копия; недопустимый epoch отклоняется в транзакции записи. Purged не восстанавливаются.

## Аудит и оптимизация

Запросы используют связанные параметры и общий контроль удаления/защиты/открытых сессий. Фильтры объединяются AND, принадлежность тегу наблюдает также tags/cross-ref. «Сегодня» определяется местной полуночью, включая23/25-часовые дни. MIN будущего срока — скалярный запрос по индексу, без загрузки тел/вложений; обычные карточки используют прежнюю выборку записей. Поиск/фильтры и MIN объединяют частые правки через300ms. Нет отдельного таймера на каждую карточку. После добавления нового индекса полный EXPLAIN-тест обнаружил выбор общего индекса вместо календарного: для count/первых3 записей календаря явно закреплён index_notes_dayKey, чтобы не сканировать все активные записи.

Один foreground wake-up до ближайшего срока/полуночи; на уходе с экрана отменяется. Возврат и системные DATE_CHANGED/TIME_SET/TIMEZONE_CHANGED пересчитывают время. Runtime receiver активен только STARTED и принимает только защищённые системные действия; EXPORTED выбран для доставки системных событий и совместимости старых API без дополнительного разрешения. В cloud-тестах прежний NOT_EXPORTED вызвал ошибку отсутствующего custom signature permission при запуске MainActivity — сквозные проверки выявили и подтвердили исправление.

Ответ БД может прийти после ближайшего срока: тогда время обновляется сразу. Старый MIN ниже времени нового запроса не вызывает цикл быстрых wake-up. При пересчёте времени уже видимые строки фильтруются по актуальной границе до готовности нового SQL; карточки не очищаются целиком и их анимации сохраняются. При смене пользовательских фильтров старые результаты скрыты до совпадения ключа. result/notes/MIN/first-photo caches сбрасываются после остановки подписок. Отмена запроса асинхронна: дополнительное поколение списка исключает снимок прошлого посещения даже до завершения очистки кеша; тест ожидает фактического завершения отмены, а не синхронного reset. Поколение публикуется в наблюдаемое Compose-состояние перед ключом нового SQL-запроса; прямое чтение StateFlow из композиции удалено по ошибке lint. Это не возвращает старую защиту при быстром повторном открытии и не удерживает содержимое вне экрана. Существующие часы/секундомеры/анимации главной сохранены.

Сохранение срока использует прежние saveMutex/свежие ID/syncId/защиту. Ошибка записи остаётся сообщением с сохранённым выбором для повторной попытки; не выходит необработанным исключением из UI callback. Новых разрешений/служб/worker/alarm для сроков нет. RU/EN новые строки и пояснение независимости срока локализованы.
