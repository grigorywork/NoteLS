# agent.md — План разработки NoteLS

## Описание проекта

Приложение заметок (клон Evernote) под Android с интерфейсом Material Design 3 и динамической темой.
Ключевая особенность — **синхронизация между устройствами без облака**: на одном устройстве генерируется QR-код, второе его сканирует, устройства связываются и синхронизируются напрямую через Wi-Fi (локальная сеть / Wi-Fi Direct).

## Правило работы

- **Один запуск = один этап + аудит.** За один запуск выполняется только текущий этап целиком, затем проводится аудит по чек-листу этапа.
- После аудита обновить процент готовности в этом файле и зафиксировать, что сделано.
- Не переходить к следующему этапу, пока аудит текущего не пройден.
- Весь UI — только стандартные компоненты Material Design, без самодельных кнопок. Выравнивание строго по сетке, тексты лаконичные.

**Общий процент готовности: 100%** (все этапы 0–7 пройдены — 2026-11-10)

> Изменение порядка (2026-11-10): по решению пользователя Этап 5 (передача данных по Wi-Fi) был выполнен раньше этапов 1–4. Затем в одном запуске закрыты этапы 2, 3, 4, 6 и 7. Единственная проверка вне песочницы — запуск на двух реальных устройствах (за пользователем).

- Протокол полудуплексный пофазный (hello → изменения сервера → изменения клиента → вложения клиенту → вложения серверу → done) — исключает гонки, одна корутина на сторону.

## Файловый обмен

Протокол/шифрование/лимиты64 и доверие65 не меняются. Реальный Room source поддерживает отдельную optional StreamingSyncDataSource capability: отправитель держит открытый descriptor и читает до256KiB, приёмник пишет во временный файл через64KiB buffer, одновременно считает SHA-256/число байтов. Нет целого вложения в ByteArrayOutputStream/toByteArray у настоящего обмена Room. Старый byte-array контракт остаётся совместимым адаптером для старых/test источников, включая Kotlin delegation: их переопределения read/write продолжают вызываться.

Общий VerifiedAttachmentSink проверяет предел при каждом write и точный размер/хеш перед публикацией. Усечение, рост источника, неожиданный chunkID, лишние/неполные байты, неверный хеш и отмена завершают сеанс без ACK/публикации неполного файла. use/close закрывают descriptor и удаляют staging при любом выходе. Успешный поток flush/fsync до короткой Room-транзакции, внутри повторная проверка существования/purge/владельца и atomic rename+обновление previewRevision/size. ## SQL и отмена

Согласованный снимок метаданных теперь содержит SQL/проекции: LEFT JOIN глобального syncId блокнота, вложения и теги пачками по200 noteIDs вместо запросов на каждую заметку.
